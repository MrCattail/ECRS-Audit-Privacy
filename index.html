ECRS Price Audit Privacy Policy

Effective August 20, 2026 · Last updated September 29, 2026

ECRS Price Audit is an internal inventory-audit tool for authorized Metro Chef staff. It does not sell user data or use it for advertising.

Purpose

ECRS Price Audit helps authorized Metro Chef staff review, maintain, and audit ECRS inventory data within the organization's configured ECRS Web Office workflow. It records item-page visits and saved changes to Base Price, Auto Discount, Item ID, Receipt Alias, item Name, Memo, Alternate ID rows, Supplier Unit ID rows, and Default Supplier selections, and displays each item's audit history. Related Item and Purchase Order editing, Inventory Search, Worksheet navigation, Receiving History, and local display and productivity tools support the same inventory-review and audit purpose.

Information handled

The extension processes the signed-in ECRS account display name, item PK, Item ID, Receipt Alias, item Name, Memo, Pricing mode, Base Price and Auto Discount values, Alternate ID rows, Supplier Unit ID rows, Default Supplier selections by Store, Last Modified value, current ECRS item-page address, timestamps, computer name, extension version, event identifiers, Save-group identifiers, and verification status. Each Alternate ID row contains Default, Scancode, Package Receipt Alias, Quantity, and Hide In WebCart. Each Supplier Unit ID row contains Default, Package Item, Supplier, Unit, Unit ID, and Quantity. Selected entities, including Package Item, Supplier, Unit, and Store, include their displayed labels and identifiers. Saved row events contain complete rows added or deleted and complete before-and-after rows plus changed-field names for modified rows. Saved Default Supplier events contain Store identity and complete before-and-after selections. Hiding columns or changing the layout does not remove these fields from qualifying audit records.

Saved Auto Discount, Item ID, Receipt Alias, item Name, and Memo changes contain old and new values. Memo is recorded only on an existing-item page after an authorized user explicitly saves a real change; each old or new Memo value is limited to 254 characters. Memo, Alternate ID, Supplier Unit ID, and Default Supplier reopen checks report matched, mismatched, or superseded status without repeating their row values or adding a third observed Memo value. Item-detail verification records also include the original saved old/new Item ID, Receipt Alias, or item Name changes, the fields checked, and the original ECRS account name.

Draft edits, Cancel, viewing without Save, and ECRS-rejected Supplier structural changes create no audit change event. Supplier and Unit are recorded only after a constrained ECRS suggestion selection settles. Save-action confirmation means the extension observed the page's Save control or exact Alt+S shortcut; the record does not identify which method was used. This is not independent proof of the server response, except that Alternate ID and Supplier structural Saves are held until the page reports or recovery proves a successful native outcome.

Receiving History loads the current item's Inventory 360 page inside the same signed-in ECRS origin and reads its native Receiving table. It displays Date Committed, Worksheet, Supplier, Unit Cost, Qty Rec'd, and Employee, together with store/date filters and pagination. The extension keeps its receiving records and filter state in page memory, not in Chrome extension storage, and does not upload them to the audit service. Store/date choices last only for the current Item browser document and reset on reload. Worksheet links open the original ECRS receiving document in a new tab. Loading, filtering, refreshing, and following links use ECRS's existing authenticated service; ECRS may retain its own records under the organization's ECRS policies.

Inventory Search uses a hidden page from the same signed-in ECRS origin to run a user-requested search. It processes the search text, match type, discontinued-item choice, sort and page state, result count, and displayed Receipt Alias, Item ID, Size, Department, Brand, and item links. Search queries, results, and filters remain in page memory, are not written to Chrome extension storage, and are not sent to the audit service. Opening a result navigates to the native ECRS Item page. ECRS receives the search through its existing authenticated service and may retain its own records under the organization's ECRS policies.

The Purchase Order inline editor opens only after a user requests an eligible existing item. A static hidden offscreen document packaged with the extension embeds native ECRS Item and, on demand, Receiving pages from the same declared ECRS host. The extension processes the current Purchase Order and item identifiers, exact route, tab and document ownership, session identifiers, and regular or Incognito context locally to bind each editor to its owner. User actions are relayed to the native ECRS page; the native Save result and the item-audit rules described above remain authoritative. Opening an inline Item source may create the same item-page visit record described above, but merely opening, expanding, collapsing, or closing the editor does not upload separate Purchase Order row data. Editor view state and unsaved drafts remain in browser memory. The offscreen document closes shortly after no authorized editor needs it or ownership is lost.

Worksheet tools read visible Worksheet rows and dates locally to apply the selected cutoff and default Purchase Order sorting. Chrome extension storage keeps only whether the date filter is enabled and its cutoff date; it does not store or upload Worksheet or order rows. The optional Purchase Order Receiving Store lock keeps the selected store value and label for each declared ECRS origin in Chrome extension storage and is not an audit event.

Custom Layout, Classic or New Art, Alternate ID grouping, field counters, Memo highlighting, and Auto Discount formula checks use existing ECRS controls and values locally. Custom Layout holds unsaved Individual and Case price drafts in page memory and synchronizes them to native controls; saving still requires the user's explicit Save action. Auto Discount checks use the current prices, formula, and eligible Alternate ID Quantity values to display a warning or suggestion; they do not change Auto Discount automatically. Item-photo viewing reads the current item's ECRS image and creates a temporary local overlay without storing or uploading the image. Copy controls write only the user-selected price, Item ID, Receipt Alias, item Name, or displayed recommended Auto Discount formula, which may reflect an unsaved draft, to the system clipboard after a click. The extension does not read the clipboard, keep a copy history, or upload a copied value as a copy event. The clipboard is controlled by the operating system and other applications after copying. The Calculator's expression, result, history, and button/panel positions remain local, are not audit records, are not uploaded, and are not written to ECRS fields.

Print Labels can temporarily show the existing ECRS Unit, Display Name, Old Price, Source Type, and Origin Power Field controls below Scancode, preserving their native suggestions, pickers, validation, and draft state. Clicking a label template requests an automatic native Preview in Original and Custom Layout. If any of these five fields has changed, the extension uses the native Item Save action before Print, Export, manual Preview, or automatic Preview and waits for a confirmed result before continuing. Item Save can also save other item-page drafts; unchanged fields do not cause an additional Save. Cancel before such an action uses the native Item Cancel control to discard the draft. After an action-triggered Save succeeds, that Save is final and closing the dialog does not restore the earlier values. Automatic preview reads the generated PDF through the existing signed-in ECRS session, displays its first page locally, and opens no new PDF tab. Manual Preview opens the complete native PDF. PDF bytes and rendered images remain temporarily in memory, are not written to Chrome extension storage, and are not uploaded to the audit service. ECRS may retain its own generated PDF and request records under the organization's ECRS policies.

While auditing an ECRS item page, the extension checks keyboard events only to recognize the exact Alt+S shortcut. It does not retain or transmit general keyboard input, individual key values, temporary Supplier or Unit search text, the shortcut source, or keystroke history. Metro Chef business rules prohibit sensitive information in Memo, but the extension does not inspect or classify Memo content. It does not upload drafts, cancelled changes, ECRS-rejected Supplier structural changes, local verification salts, or local verification digests. It does not read or store ECRS passwords, browser cookies, unrelated browsing activity, payment-card data, personal financial information, health information, personal communications, precise location, or complete page HTML.

Use and sharing

Qualifying audit records, including complete Alternate ID and Supplier Unit ID added/deleted rows, modified before-and-after rows, and Default Supplier changes by Store, are sent over HTTPS to Metro Chef's secured audit service, hosted by Supabase as a service provider. They are used to provide, maintain, and secure internal inventory auditing. The service and hosting provider may process standard connection metadata, such as IP addresses, to deliver and secure requests. A per-computer device token stored locally authenticates these requests and is not included in audit-event records. Receiving History records, Inventory Search queries and results, Worksheet and Purchase Order rows, item images, Auto Discount suggestions, Calculator data, clipboard contents, unsaved drafts, and other local-only display or editor state are not sent to the audit service.

Metro Chef does not sell audit data, use it for advertising, use it to determine creditworthiness or for lending, or transfer it for purposes unrelated to the extension's single purpose. ECRS Price Audit's use and transfer of information complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

Local storage and security

Chrome extension storage holds configuration and page-detection selectors, computer name and device token, disclosure choices and migration provenance, notice and update state, cached audit-service capability information, display and appearance preferences, Alternate ID grouping mode, Worksheets date-filter status and cutoff date, per-origin Receiving Store lock choices, queue-health and recovery state, unsynchronized or rejected audit records, pending verification candidates, Calculator history, and normalized Calculator button/panel positions. A stored Receiving Store choice contains the selected store value and displayed label. Queued or rejected records may contain full old/new Memo values and qualifying Alternate ID and Supplier row evidence. Records awaiting upload remain local until delivery succeeds; rejected records can be retried or exported and removed only after confirmation of the exact exported revision. Consent provenance, notice state, and the estimate of a possible version 0.3.0 audit interruption remain local and are not uploaded as audit events. Separately, a bounded diagnostic log of up to 80 entries is kept in the ECRS page's session storage. It may contain the ECRS account display name, item identifiers and names, Pricing mode, and observed name changes, with strings limited to 200 characters. This page-session log is not uploaded as audit events.

Chrome extension storage also keeps at most 100 Print Labels Power Field 1 Save diagnostics for seven days, deleting expired and then oldest entries first. Successful entries contain random event and session identifiers, item PK, the stable Power Field 1 field name, its configured display title, operation, timestamp, result, and the exact ECRS-accepted old and new values. Failed, timed-out, and context-changed attempts retain only the same bounded metadata and a limited error code; they do not retain failed draft text, account names, full page addresses, or native error messages. These diagnostics are not audit events, are not shown in Audit History, are not included in rejected-record export, and are never uploaded to the audit service.

During an Alternate ID or Supplier structural Save, the complete candidate audit batch, including its before/after row values, may be held temporarily in extension storage while waiting for or recovering the native ECRS Save result. The Alternate ID, Supplier, and combined structural-hold stores each allow up to 20 batches. A verified Save releases a batch for normal delivery. A failed or irrecoverable Save discards it without uploading a change event; an unresolved result remains blocked until a safe outcome is established.

The extension keeps up to 100 seven-day verification candidates separately for item details, Memo, Alternate ID, Supplier Unit ID, and Default Supplier. Item-detail and Memo candidates retain the saved changes needed for comparison. The longer-lived Alternate ID, Supplier Unit ID, and Default Supplier reopen-verification candidates contain only a per-installation salted SHA-256 digest of the expected normalized row set, row count, parent event ID, item PK, visit ID, and timestamp; they do not duplicate raw row values. The local candidate-store objects, salts, and digests are not uploaded. Memo and row-verification events report terminal status without repeating their saved values; item-detail verification events also contain the original saved field changes described above. A newer Save for the same item and family supersedes its older candidate. If a candidate store remains full after expiry cleanup, valid existing candidates are preserved, the new candidate is rejected, and a persistent severe warning appears only in the Popup; the saved change event remains recorded.

Within the same Chrome profile and extension installation, regular and Incognito windows share device configuration, disclosure choices, display and layout settings, Alternate ID grouping mode, Worksheets date-filter settings, Receiving Store lock choices, audit recovery data, Calculator history, and Calculator positions. Closing Incognito windows does not itself erase these locally retained records, settings, or tool data. Calculator data, Worksheets settings, and Receiving Store lock choices are not uploaded as audit events. Receiving History records, Inventory Search state, editor view state, and unsaved drafts remain in page memory as described above. Regular and Incognito ECRS logins, website cookies, and offscreen editor sources remain separate; the extension does not copy those sessions or read ECRS passwords or cookies.

Audit-service communications use HTTPS. Device tokens, passwords, and browser cookies are not included in audit records. The extension does not download or execute remotely hosted code.

Choice and control

Auditing remains disabled until the disclosure is accepted and device setup is complete. Supplier auditing uses the ecrs-inventory-audit-v2 scope: earlier v1 or legacy acceptance is not inherited, and an authorized user must manually accept the expanded scope. A valid acceptance may be carried forward only across later disclosure revisions within the exact v2 scope family. Clearing the checkbox and saving disables auditing and prevents later automatic inheritance until manual acceptance. Authorized users can inspect queue health, retry or export rejected records, and remove only the exact rejected-record revision that was exported. This privacy-text update does not change the audit-data scope or bypass the consent gate.

If a user manually enables Chrome's Allow in Incognito setting, the same audit collection and HTTPS upload described in this notice apply to authorized ECRS pages in Incognito. The existing disclosure choice and valid device setup are still required. Device & Page Detection, Audit Data Disclosure, and Privacy Notice open in a regular Chrome window; saved configuration and disclosure choices also apply in Incognito. Closing all Incognito windows does not itself remove queued or rejected audit records, pending verification candidates, or audit records already delivered to the organization's service. Queued records may be delivered later when auditing is enabled and a connection is available; existing retry, expiry, recovery, and server-retention rules continue to apply.

Retention and requests

Server retention, access, correction, and deletion are controlled by Metro Chef's approved internal audit policy and authorized administrators. Uninstalling the extension does not delete audit records already delivered to the organization's service.

For privacy questions or requests, email customer.service@metrochef.com or use the Metro Chef contact page. Do not send passwords, device tokens, or other credentials in a support request.
