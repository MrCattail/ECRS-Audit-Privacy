ECRS Price Audit Privacy Policy

Effective August 20, 2026 · Last updated August 31, 2026

ECRS Price Audit is an internal inventory-audit tool for authorized Metro Chef staff. It does not sell user data or use it for advertising.

Purpose

ECRS Price Audit supports Metro Chef's internal inventory-audit process. Its single purpose is to record authorized ECRS inventory item-page visits and saved changes to Base Price, Auto Discount, Item ID, Receipt Alias, item Name, Memo, and Alternate ID rows so authorized staff can review who saw or changed an item.

Information handled

The extension processes the signed-in ECRS account display name, item PK, Item ID, Receipt Alias, item Name, Memo, Pricing mode, Base Price and Auto Discount values, Alternate ID rows, Last Modified value, current ECRS item-page address, timestamps, computer name, extension version, event identifiers, Save-group identifiers, and verification status. Each Alternate ID row contains Default, Scancode, Package Receipt Alias, Quantity, and Hide In WebCart. A saved Alternate ID event contains complete rows that were added or deleted and complete before-and-after rows plus changed-field names for rows that were modified. Draft edits, Cancel, and viewing the table without Save do not create or upload an Alternate ID change event. For saved Auto Discount, Item ID, Receipt Alias, item Name, and Memo changes, the audit record contains the old and new values.

Memo is recorded only on an existing-item page after an authorized user explicitly saves a real change, and each old or new Memo value is limited to 254 characters. Reopen checks record only matched, mismatched, or superseded status and do not repeat Alternate ID row values or store a third observed Memo value.

A save-confirmed record means the extension observed an explicit Save action through the page's Save control or the exact Alt+S shortcut; it is not independent proof of the ECRS server response. The audit record does not identify which of those two methods was used.

While auditing an ECRS item page, the extension checks keyboard events only to recognize the exact Alt+S shortcut. It does not retain or transmit general keyboard input, individual key values, the shortcut source, or keystroke history. Metro Chef business rules prohibit sensitive information in Memo, but the extension does not inspect or classify Memo content. It does not upload Alternate ID drafts, cancelled changes, the local Alternate ID verification salt, or the local verification digest.

A per-computer authentication token is stored in Chrome extension storage and sent over HTTPS to authenticate requests to the audit service. It is not included in audit-event records.

The extension does not read or store ECRS passwords, browser cookies, unrelated browsing activity, payment-card data, personal financial information, health information, personal communications, precise location, or complete page HTML. The floating Calculator is local convenience functionality: its expression, result, history, and saved button and panel positions are not audit records, are not uploaded, and are not written to ECRS fields.

Use and sharing

Audit data is used only to provide, maintain, and secure the internal ECRS audit feature. Records, including qualifying complete Alternate ID added or deleted rows and modified before-and-after rows, are sent over HTTPS to Metro Chef's secured audit service, which is hosted by Supabase as a service provider. The service and hosting provider may necessarily process standard connection metadata, such as an IP address, to deliver and secure requests. Calculator data is never sent to the audit service.

Metro Chef does not sell audit data, use it for advertising, use it to determine creditworthiness or for lending, or transfer it for purposes unrelated to the extension's single purpose. ECRS Price Audit's use and transfer of information complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

Local storage and security

The extension stores its configuration and page-detection selectors, display preferences, per-computer authentication token, local disclosure choice, consent-migration provenance, disclosure-notice state, extension and update status, queued audit records, permanently rejected records, queue-health diagnostics, pending verification candidates, Calculator history, and normalized Calculator button and panel positions in Chrome extension storage.

Consent-migration provenance, notice state, and the dismissible estimate of a possible version 0.3.0 audit interruption are local-only and are not uploaded as audit events. Unsynchronized or rejected records, including full old and new Memo values and qualifying Alternate ID row evidence, remain locally until upload succeeds or an authorized user retries them, exports them, and confirms removal of the exact rejected revision.

Up to 100 item-detail verification candidates, a separate 100 Memo verification candidates, and a separate 100 Alternate ID verification candidates are kept locally for seven days. An Alternate ID candidate contains only a per-installation salted SHA-256 digest of the expected normalized full row multiset, row count, parent event ID, item PK, visit ID, and timestamp; it does not duplicate the five raw row values. The local candidate, salt, and digest are not uploaded as audit events; only the terminal verification status is sent separately. A newer Alternate ID Save for the same item supersedes its older candidate. If a candidate store remains full after expired and invalidated entries are removed, existing valid candidates are preserved, the new candidate is rejected, and a persistent severe warning appears only in the extension Popup; the saved change event itself remains recorded. Device tokens, passwords, and browser cookies are not included in audit records.

All audit-service communications use HTTPS. The extension does not download or execute remotely hosted code.

Choice and control

Auditing remains disabled until the extension's data disclosure is accepted and device setup is complete. A structurally valid choice previously accepted in the same Chrome extension installation may be carried forward when its disclosure date is not newer than the current version and its audit-purpose family remains compatible. The original acceptance time is preserved; this is not recorded as a new manual acceptance.

Clearing the disclosure checkbox and saving disables auditing and prevents later automatic inheritance until an authorized user manually accepts it again. Authorized users can inspect queue health, retry or export rejected records, and clear only the exact rejected-record revision that was exported.

Retention and requests

Server retention, access, correction, and deletion are controlled by Metro Chef's approved internal audit policy and authorized administrators.

For privacy questions or requests, email customer.service@metrochef.com or use the Metro Chef contact page. Do not send passwords, device tokens, or other credentials in a support request.
